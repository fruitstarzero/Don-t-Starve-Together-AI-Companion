# 测试、部署与交接模板

## 1. 分层验证，不混写结论

| 层级 | 证明什么 | 不能据此证明什么 |
| --- | --- | --- |
| 语法/编译/API核对 | 代码能解析、类型/引用正确、接口存在 | 游戏动作真正成功 |
| 本地逻辑回归 | 状态机、权限、过期、计数、取消、模型错误等 | 模拟环境完全等同游戏 |
| 原生专项 | 当前游戏引擎内某条动作/机制的实际效果 | 玩家全部体验、所有模组组合 |
| 模型往返 | 当前模型能处理快照、产生合法结构化结果 | 每个游戏动作都执行成功 |
| 玩家实测 | 当时版本、世界和输入下的真实体验 | 后来版本或其它玩法全通过 |

修复后应重跑受影响项目，并在合适时完成一次全量本地回归。分批合并覆盖不改写成“最终单轮全通过”；没有新模型成功证据就不能用错误提示或旧探测替代。

本次资料整理没有重新跑游戏或模型。文档中的测试数字是已核对的历史记录，见来源导航。

## 2. 通用回归矩阵

| 类别 | 最少覆盖场景 | 核对内容 |
| --- | --- | --- |
| 身份 | 非主人、其他世界、过期会话 | 不接受越权指令，不串记忆 |
| 过期/幂等 | 新命令期间老模型返回、结果重送、阶段已完成 | 旧任务不复活，物品不重复生成/扣除 |
| 普通对话 | 工作途中问攻略、否定、例子、假设 | 不把问答当操作，不暂停/清掉工作 |
| 主动交流 | 候选过期、模型沉默、重复话题、问题解决 | 有冷却、可沉默，不修改动作 |
| 暂停恢复 | 跟随、待命、回家、集合、撤退后再恢复 | 保留原步骤和累计，等待明确恢复 |
| 生存打断 | 自然天黑、补给、战斗、死亡/复活 | 先保命，条件恢复后重查任务 |
| 目标变更 | 明确取消、新目标替换、恢复自主 | 取消终态保留，旧目标不复活 |
| 多步计划 | 中间步骤重试、暂停期间完成动作 | 成功才推进一次，不跳过或多做 |
| 物品 | 拆堆、整件工具、叠堆、取存回调 | 实际位置和数量守恒，留个人补给 |
| 制作 | 中间材料、科技不匹配、空间满、位置非法 | 不重复扣料、不无限递归、不伪造落地 |
| 仓储 | 箱满/包满/双满、箱被占用、暂存物资 | 有条件扩容，暂存有界且可回收 |
| 长期项目 | 菜地记忆、取消、重进、闲时检查 | 有位置与取消证据，不抢占手动模式 |
| 模型故障 | 超时、错误、额度耗尽、断开网络 | 明确失败，本地策略符合设计，不刷请求 |
| 存档 | 更新前后、主人暂停时、任务中途保存 | 人物/物品/任务恢复且只有一份 |
| 模组/客户端 | 单模组基线、组合加载、受限全局、UI编辑态 | 能进入世界，输入清晰，专属能力不夸大 |

测试选择与改动相匹配，不为无关文档变更反复运行游戏。实机测试暂缓时，保留完整清单，不暗中启动客户端或测试服。

## 3. 验证记录模板

```text
版本/源码提交：
日期、游戏版本、框架版本：
测试环境：本地模拟 / 原生专项 / 玩家实测 / 模型往返
是否调用模型、是否进入世界：
输入和初始条件：
预期行为：
实际观察（日志/事件/数量/位置）：
通过/失败/待验证：
失败原因和修复提交：
修复后复核范围：
证据文件位置：
尚不能证明的内容：
```

真实模型探测优先使用虚构状态做小范围结构化测试，避免为了测试额外发送私人聊天。必须排除 `modelError`、turn.failed、超时和不合法输出。

## 4. 下次游玩清单模板

每项说明“你说什么、准备什么、观察什么”，不把工程细节交给玩家。采用测试存档，避免要求故意濒死或消耗珍贵资源。

1. 进入测试世界，打开远程面板，确认状态与中文输入。
2. 安排一个简单任务，途中问一句攻略，确认解释后继续工作。
3. 临时叫到身边或跟随，再待命；等待一会不应自行走开，说“继续原任务”后继续。
4. 安排两到三个已适配步骤，观察每步真正成功后推进；核对最终物品和个人补给。
5. 自然缺料/空间不足时观察具体求助，补足条件后确认能重查。
6. 明确取消或更换任务，确认旧目标不再回来。
7. 正常保存退出，下次重进确认人物、背包、地点和任务进度。
8. 继续正常玩，观察移动、协助、发言节奏及模组冲突。发现问题只需记录输入、地点、行为和原始错误。

## 5. 部署顺序

1. 确认源码与要发布的版本，记录测试证据和已知限制。
2. 检查游戏和专服是否真实运行。文件被占用时等玩家正常保存退出，不强杀正在游玩的进程。
3. 备份旧模组、桥接、必要配置；需要操作世界时另备份世界，并限定修改范围。
4. 更新程序与文档，保留用户现有认证、主人配置和私人记忆。不要用开发默认值覆盖。
5. 如果只需桥接更新，只停止已核对路径的该服务PID；不要结束QQ、其它游戏或不相干Node进程。
6. 启动需要的后台服务，核对health服务身份、版本、关键文件哈希和测试清单副本。
7. 启动入口放在安装者自选的统一管理目录。本次若只整理资料，不需要更改启动项或重启服务。
8. 记录备份目录、已部署版本、回退步骤和实机待测事项。

卸载/回退之前考虑同伴持有物品、旧版能否读取新版存档；程序备份不等于存档备份。不要删除新保存的世界来强行回退程序。

## 6. 新项目交接模板

```text
目标与用户最新要求：
本轮授权范围（含通知和实机测试）：
游戏/框架/平台/联机方式：
工作仓库、行为基线提交：
生产目录、游戏模组目录、启动入口：
同伴实体方案和近似机制：
协议字段、动作白名单与任务状态：
模型入口/认证来源（只记位置，不附密钥）：
人设、记忆共享范围、世界隔离方式：
保存/加载/迁移与资源守恒策略：
本轮已改文件与原因：
已验证内容、命令、证据与限制：
未通过/尚未实现/暂缓测试：
现有进程状态（核对时间）：
更新备份、回退办法：
下一步优先事项与玩家清单：
不能触碰的私人文件/原存档：
```

交接必须让后来的人分清“已经做完”“只是研究过”和“下一步建议”。不要把计划表改写成已实现清单。
